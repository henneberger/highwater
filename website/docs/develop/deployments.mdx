---
title: Deployments
description: Run application workers separately from durable service ownership.
---

Highwater separates durable ownership from application execution. Deploy the Python worker with your normal container platform and point it at the private execution endpoint:

```bash
highwater-worker app --target "$HIGHWATER_EXECUTION_ADDRESS"
```

Build an immutable application image from the published worker base:

```dockerfile
FROM ghcr.io/henneberger/highwater-worker@sha256:WORKER_IMAGE_DIGEST
WORKDIR /app
USER root
COPY requirements.txt /app/requirements.txt
RUN pip install --no-cache-dir --requirement /app/requirements.txt
COPY app.py /app/app.py
USER 65532:65532
```

Push that image, resolve its platform-index digest, and pass the digest to the hosted deployment renderer. The worker base contains the SDK, native engine utilities, and worker entry point. Your image supplies the application module and its dependencies.

Clients and operators use the public endpoint:

```bash
export HIGHWATER_ADDRESS=https://api.highwater.cloud
export HIGHWATER_API_KEY=...
highwater workflow describe --id ORDER_ID
```

Worker access belongs on a private network. The execution gateway is separate from public ingestion and does not expose storage, checkpoints, or administration.

## Scope worker identity

Set `HIGHWATER_EXECUTION_TOKEN` from a secret mounted into the worker. The service identity maps that token to one task queue and an allowlist of build IDs. A worker cannot poll another deployment or present an unapproved build.

Production deployments use separate listeners:

```bash
highwater-server \
  --listen 0.0.0.0:7233 \
  --execution-listen 0.0.0.0:7234 \
  --api-token-file /run/secrets/public-api-token \
  --execution-identity-file /run/secrets/execution-identities.json
```

Expose the public listener through the application API. Route the execution listener only to application workers.

## Apply the worker sandbox

The repository includes a [reference Kubernetes worker profile](https://github.com/henneberger/highwater/blob/main/deploy/sandbox/worker.yaml). It selects gVisor and runs the application as UID 65532 with a read-only root filesystem. Linux capabilities, privilege escalation, ingress, and service-account credentials are disabled. CPU, memory, process count, and temporary storage are bounded.

The default network policy permits DNS and the private Highwater execution endpoint. Add explicit egress rules for each model or service the application calls.
