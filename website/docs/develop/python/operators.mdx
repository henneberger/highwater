title: Streaming operations
description: Express stateful stream work in Process handlers.
---

A Process is the public programming model. Start it from a source stream, then write ordinary Python in its event handler.

```python
catalog = streaming.versioned("catalog", key="product_id")

@streaming.process(key="user_id")
@dataclass
class Recommendation:
    recent: list[str] = field(default_factory=list)

    @streaming.event
    async def recommend(self, view, context):
        product = await catalog.get(
            view.product_id, as_of=context.event_time
        )
        self.recent.append(product.category)
        return await model.rank(product=product, recent=self.recent)

recommendations = await client.start(
    Recommendation,
    source="product-views",
)
```

Highwater discovers the versioned dependency from the handler and compiles the execution graph during deployment. The application does not maintain a topology object.

## Event-time lookups

`await catalog.get(..., as_of=context.event_time)` reads the version that applied when the event occurred. The Process waits for the catalog stream to become complete through that time before it runs.

## Stateful decisions

Dataclass fields hold keyed state. A handler may update them, emit a result, await application services, and read versioned stream state in one flow.

## Adaptive batches

Use `@streaming.batch(max_size=..., max_delay=...)` when an operation benefits from vectorized work. Highwater dispatches a batch when its size limit or latency limit is reached.
