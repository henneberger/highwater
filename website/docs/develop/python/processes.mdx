---
title: Processes
description: Model ordered, durable state transitions around a business key.
---

A Process is a durable state machine with one instance per key.

```python
from dataclasses import dataclass
from highwater import streaming

@dataclass(frozen=True)
class Authorization:
    account_id: str
    authorization_id: str
    amount: int

@streaming.process(key="account_id")
@dataclass
class Account:
    available: int = 0

    @streaming.event
    async def authorize(self, event: Authorization):
        if event.amount > self.available:
            return {"approved": False}
        self.available -= event.amount
        return {"approved": True, "remaining": self.available}
```

Highwater guarantees one committed transition at a time for each `account_id`. Different accounts execute independently.

## Keep transitions replay-safe

Process state changes become visible only when the invocation commits. Code may run more than once after a timeout or host failure, so direct external effects must use a stable idempotency key. Prefer returning output from the handler; Highwater publishes committed output with a stable message identifier.

## Event-time gates

Use a completeness gate when a transition depends on source progress:

```python
@streaming.process(
    key="account_id",
    event_time="occurred_at",
    wait_until=streaming.complete,
)
@dataclass
class Account:
    @streaming.event
    async def apply(self, event):
        return {"account_id": event.account_id, "complete": True}
```

An event remains in the durable Process inbox until the source watermark reaches its event timestamp. Waiting events do not hold worker capacity.

## Hot keys

Ordering means one key cannot commit two conflicting transitions concurrently. Choose the narrowest key that preserves the invariant you need. Split a globally keyed Process only when the state can be partitioned safely.
