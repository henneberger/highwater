---
title: Safe upgrades
description: Change Process code and state without reinterpreting in-flight work.
---

Every deployment is immutable and versioned. Highwater records which code version and state schema own each Process activation.

## Compatible changes

Additive handlers and optional state fields with defaults can usually roll forward directly:

```python
@streaming.process(key="account_id", state_version=2)
@dataclass
class Balance:
    total: int = 0
    currency: str = "USD"
```

## State migrations

Declare an explicit migration when an older state needs transformation:

```python
@Balance.migrate(from_version=1)
def add_currency(state):
    return {"total": state["total"], "currency": "USD"}
```

Migrations are deterministic, versioned, and committed with the first event using the new schema.

## Rollout

```bash
highwater-worker app --target "$HIGHWATER_EXECUTION_ADDRESS"
```

The platform validates definitions, starts the new version, routes new activations only after it is ready, and drains work pinned to the previous version. Rollback changes routing; it never asks old code to decode newer state.

Renaming a Process, changing its key, or changing event identity is a data migration. Deploy it as a new Process and backfill or redirect explicitly.

## Compare two builds before activation

Retain the Process input stream when a deployment needs replay comparison. Highwater can run the retained events and versioned reference history through two decorated Process definitions:

```python
comparison = await client.compare_builds(
    "shopping-assistant",
    baseline=ShoppingAssistantV1,
    candidate=ShoppingAssistantV2,
)

for difference in comparison.differences:
    print(
        difference.event_id,
        difference.baseline_state,
        difference.candidate_state,
        difference.baseline_output,
        difference.candidate_output,
    )
```

Comparison writes no Process state or output. Each difference identifies the original event and key. Versioned lookups resolve at the original event time.

The comparison executes both handlers. Supply recorded responses or evaluation implementations for model, tool, and service calls. This keeps external effects out of the comparison and makes nondeterministic dependencies repeatable.
